# REQ-125: One signed-in user per request, and isolation between users

Why: the code today serves one fixed user (`current_user_ref()` returns `"owner"` in 17 places across 6 route files,
ADR-051's owner-only phase). Before a second user signs in, every read, write and live stream must be scoped to the
caller, or one user's positions, plans or alerts can leak to another. REQ-003 AC-1 states isolation as a goal; this
requirement turns it into checks a test can fail.

Example: user A (Client ID AB1234) and user B (Client ID CD5678) are both signed in. A opens
`/strategies/15` (B's iron condor) by typing the URL: the page shows "Strategy not found", the server logs a
cross-user attempt for A, and B's legs, P&L and plan never leave the server.

Attack cases the suite must hold: guessed ids (AC-3, AC-4), a replayed socket subscription (AC-6), another user's tag
(AC-7), a forged user header or body field (AC-1).

Decisions: ADR-021, ADR-022, ADR-040, ADR-105 (and ADR-051 for the owner-only phase this ends). Register rows: MR-128, MR-129. Timing of the multi-user build
is the prioritisation pass (MR-130).
