## Gate decisions (delegated overnight, ADR-045; W-014)
- A new entry or an exit runs the active version; an adjustment runs a proposed version (Q191).
- Contract eligibility not yet checked with Zerodha blocks execution (fail closed).
- A duplicate leg (same contract twice) blocks until the user fixes it; legs are never merged silently.
- A reconciliation mismatch on this strategy blocks exits too: acting on a wrong picture of positions could open an
  unintended naked position; the user can still act in Kite (ADR-019). A mismatch on another strategy does not block
  this one (REQ-060 AC-7).
- A Limited user may run an adjustment only if no position grows (no new contract, no quantity increase, no side flip)
  AND the engine's worst-case loss does not get worse (min P&L after >= before; an UNLIMITED loss is always worse).
  Closing only the bought wing of a spread reduces size but raises risk, so it needs Pro (ADR-037: risk-adding
  adjustments stay behind Pro); closing all legs, or reducing all legs together, is a partial exit and is allowed.
- No quantity cap beyond margin; Zerodha's own checks are the authority (ADR-016).


# REQ-059: Pre-execution safety checks and validation

Execution is blocked unless every safety condition holds; validation never changes the user's strategy.
