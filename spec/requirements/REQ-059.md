## Gate decisions (delegated overnight, ADR-045; W-014)
- A new entry or an exit runs the active version; an adjustment runs a proposed version (Q191).
- Contract eligibility not yet checked with Zerodha blocks execution (fail closed).
- A duplicate leg (same contract twice) blocks until the user fixes it; legs are never merged silently.
- A reconciliation mismatch on this strategy blocks exits too: acting on a wrong picture of positions could open an
  unintended naked position; the user can still act in Kite (ADR-019). A mismatch on another strategy does not block
  this one (REQ-060 AC-7).
- **SPEC CHANGE (2026-09-29, joint decision of the orchestrator and an independent reviewer, ADR-045; replaces the
  entry-price rule written earlier the same night, which blocked hedged partial exits because the credit of closed
  legs counted before but not after).** A Limited user may run an adjustment only if (a) no position grows (no new
  contract, no quantity increase, no side flip) AND (b) the worst case AT EXPIRY after the change is no worse than
  before, computed with option premiums excluded (options at intrinsic value, futures at level minus entry price),
  at level 0, every strike and the upper tail; an UNLIMITED result after the change is allowed only if the position
  was already UNLIMITED and its upper-tail slope does not get steeper. (c) A full exit or reducing every leg by the
  same share is always allowed (ADR-037). (d) Multi-expiry positions (calendars): only a full exit, a same-share
  reduction or closing only short options is allowed; anything else needs Pro. The premium-free worst case must also
  not get lower at level 0 or at any strike even when the upper tail stays UNLIMITED at the same slope (closing the
  bought put wing of a short strangle with a put wing: -13,000 -> -1,495,000 at level 0, needs Pro).
  Examples on the 2-lot golden Iron Condor (premium-free worst case): closing only the bought 22,800 PE wing
  -26,000 -> -2,990,000 (needs Pro); closing the whole put spread -26,000 -> -26,000 (allowed); reducing the sold
  23,000 PE 2 -> 1 lot (allowed); closing one leg of each of two bull put spreads -26,000 -> -39,000 (needs Pro);
  closing the long future of a covered call -> UNLIMITED (needs Pro).
- No quantity cap beyond margin; Zerodha's own checks are the authority (ADR-016).


# REQ-059: Pre-execution safety checks and validation

Execution is blocked unless every safety condition holds; validation never changes the user's strategy.

Decisions: ADR-016, ADR-017. Sources: M §79, §80, §81; C-file (real Q numbers: spec/traceability/question-register.md).
- **SPEC CHANGE (2026-09-29, joint decision after the W-014 adversarial review, ADR-045) — which checks apply to an
  EXIT.** AC-1 lists every check for every execution; applied to exits it trapped users in positions (an exit was
  blocked for unknown margin, for a contract "not accepting fresh orders", for an invalid rule). An EXIT requires:
  market open, broker connected, session valid, every contract exists, quantities valid (reduce-only against the
  active positions, positive, a multiple of the lot size), no unresolved reconciliation mismatch for this strategy,
  dependencies satisfied. An EXIT does not require margin sufficiency, fresh-order eligibility or rule validity;
  unhealthy data is shown as a warning the user confirms, not a block. An order labelled EXIT that opens, grows or
  flips any position is refused (it is not an exit). Entries and adjustments keep every AC-1 check.
- Any internal error while checking fails closed: execution is blocked and the blocked-execution record is written.

## Owner decision (2026-09-29, Q239): which gate checks apply to exits
- Exit and closing orders stay allowed for every user (ADR-037), and the pre-execution gate still applies five checks
  to them: (1) the strategy version is in a valid state, (2) the index is supported, (3) the expiry has not passed,
  (4) the contract is still listed, (5) no duplicate legs. Each blocks only an order Zerodha would reject or one that
  would double an exit, and gives a clearer message than a broker rejection (e.g. "Expiry passed" for a 23,400 CE that
  expired yesterday).
