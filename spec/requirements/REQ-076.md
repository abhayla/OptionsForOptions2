- id: AC-1
  text: >-
    Every option leg row has a - and a + button that move that leg to the next lower or higher strike that the leg
    picker would offer for the leg's underlying and expiry (listed, not expired; REQ-035 AC-8), read from the
    instrument file, never strike plus a typed constant. Example: NIFTY 27 Oct 23000 CE, + gives 23050 CE when 23050 is

    listed strike the button is disabled and says why. A futures leg has no stepper.
- id: AC-2
  text: >-
    A stepped leg is a new contract, so its planned entry is captured again from that contract's LTP (mid of bid and
    ask when it has no LTP) with the new capture time (ADR-068 (1)); the other legs keep theirs. Example: 23000 CE
    planned 81.30 at 10:35:12 IST, + gives 23050 CE planned 62.10 captured at 10:36:40 IST.
- id: AC-3
  text: >-
    Every stepper, multiplier and toggle edit sends the edited definition to the server and every number on screen is
    drawn from the engine's reply (ADR-008); the browser computes no P&L, payoff, margin or Greek. While a reply is
    pending the old numbers are marked as updating; late replies follow REQ-119 (an older reply never draws over a
    newer edit).
- id: AC-4
  text: >-
    A strategy-level multiplier (whole numbers 1 to 50) sets each leg's lots to that leg's base lots times the
    multiplier; setting it back to 1 returns every leg to its base lots. Example: a 1-lot NIFTY iron condor, multiplier
    3, shows 3 lots per leg = 195 quantity per leg (lot size read from the instrument file; 65 on 2026-10-21), and the
    engine returns three times the max loss and the margin. The saved definition stores the resulting lots.
- id: AC-5
  text: >-
    Lots are shown by default; every user can switch to quantity with a Lots/Quantity setting (REQ-030 AC-7), and
    quantity is always lots times the
    lot size read from the instrument file for that contract, never a typed lot size. A leg whose multiplied quantity
    is above its freeze limit shows the ADR-092 block reason on that leg; it is never split (level wording removed by
    ADR-168 (4), 2026-10-24).
- id: AC-6
  text: >-
    Each leg has an "include in the numbers" tick box, ticked by default. Unticking a leg removes it from every number
    on screen (summary, payoff, scenario table, margin, Greeks), recomputed by the engine for the remaining legs; the
    unticked leg stays visible, greyed, labelled "Left out of the numbers". Example: a NIFTY iron condor with the
    bought upper CE unticked shows Max loss "Unlimited" (with the bought 22,400 PE unticked instead, the max loss grows
    but stays finite: a naked short put loses at most its strike less its premium, times the quantity; example corrected
    2026-10-24 at builder row 20, the rule is unchanged).
- id: AC-7
  text: >-
    Execute Strategy is refused while any leg is unticked, with the reason "Tick every leg to execute: the whole
    strategy is sent as one plan." The tick state is never saved and never reaches the execution plan: the Execute path
    builds from the saved definition, which carries no exclusion. This is stricter than Sensibull, which sends only the
    ticked legs ("Trade 3"), and stays so under ADR-152 exception (a) (ADR-002, ADR-017).
- id: AC-8
  text: >-
    The leg list shows the name of the template the engine matched for the current leg set (REQ-028 AC-3), for example
    "Iron Condor"; a set matching no template reads "Custom Strategy" (REQ-028 AC-4, Q52). Legs the matched template
    marks as protective carry a "Hedge" mark. Name and marks come from the server reply and update on every edit.
    Unequal wings do not change the name (ADR-186 (4), as in Sensibull): 22,500 / 22,800 PE with 23,200 / 23,400 CE
    reads "Iron Condor" with both BUY legs marked Hedge.
- id: AC-9
  text: >-
    The shape name is a label only: it never adds, removes, reorders or changes a leg (REQ-030 AC-14). Example: four
    legs SELL 22800 PE, BUY 22600 PE, SELL 23200 CE, BUY 23400 CE read "Iron Condor" with the two BUY legs marked
    Hedge; changing the 23400 CE to a 23200 PE makes it "Custom Strategy" with no hedge marks.
- id: AC-10
  text: >-
    Empty and stale states: with no legs the builder shows "No legs yet" with Add leg and Pick from Option Chain, and no
    numbers (never zeros). Steppers, multiplier and toggles keep working without live data; a number that needs a
    price the server does not have shows unavailable with its reason, never a stale price as current (ADR-015,
    REQ-049).

# REQ-076: Builder leg rows

Why: a user planning a strategy mostly nudges what they already have - one strike up, twice the size, "what if I drop
this hedge?" - and needs to know what shape they have built. Sensibull's builder does all four on each leg row
(study 2026-10-21); ADR-152 makes that the default. The one place OFO2 stays different is the leg toggle: it changes
the analysis only, never what Execute sends (AC-7; owner decision ADR-163: Execute always sends the whole strategy, and trading fewer legs means removing them from the strategy first).

Register: MR-005 (DECIDED; REQ-028 had no AC for showing the name in the builder), MR-007, MR-010, MR-011.

Decisions: ADR-152, ADR-163, ADR-002, ADR-006, ADR-008, ADR-017, ADR-068, ADR-092.
