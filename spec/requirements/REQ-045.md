# REQ-045: Adjustment detection and triggers

The platform detects adjustment opportunities from user rules and from its own monitoring, clearly labelled.

Decisions: ADR-011. Sources: M §31, §32; C-file (real Q numbers: spec/traceability/question-register.md); H2 §13.

**Open:** Legal review of personalised adjustment logic: Q211. See `spec/open-questions.md`.

## Owner decision (2026-09-29, Q252): default playbooks vs "no user rule"
- Shipped default playbooks (AC-7) that the user has **not adopted or edited** count as **platform detection**: they
  raise "Adjustment opportunity detected" with generic possible approaches only, never a specific configuration
  (AC-5, Q149, Q159). Once the user **adopts or edits** a default, it becomes the user's own rule and raises "Your rule
  was triggered". Editing makes a personal copy; it never changes the platform-wide default for anyone else.

## Owner decision (2026-09-29, Q253): what the platform detects as a "risk area" (AC-2)
A platform detection ("Adjustment opportunity detected", generic approaches only) fires when ANY one holds; every
threshold is an admin setting with these defaults:
1. the index is within **0.5%** of a short strike or of a breakeven (e.g. NIFTY 23,375 vs the golden condor's
   23,400 CE short strike);
2. the unrealized loss reaches **50% of the strategy's max loss** (golden condor: −₹4,088 of ₹8,175);
3. **2 or fewer days to expiry** while a short leg is within **1%** of the money.
Each detection names the condition that fired and its exact numbers (REQ-046 AC-1).
