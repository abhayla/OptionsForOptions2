# REQ-063: Security boundaries

Integrations sit behind adapters and no client-side code can bypass a safety rule.

Decisions: ADR-029. Sources: M §70, §85; C-file (real Q numbers: spec/traceability/question-register.md).

**Open:** Detailed security architecture and data retention: open. See `spec/open-questions.md`.

**Findings (spec/findings.md, 2026-10-02):** F-06 - SEBI's retail algo framework (circular 4 Feb 2025; NSE INVG67858)
requires order placement from a whitelisted static IP (Zerodha rejects others from 1 Apr 2026), an algo ID on API
orders and a kill switch; unverified from secondary sources, open for owner decision as Q258. F-08 - comparable
platforms keep broker tokens encrypted server-side and give clients only the platform's own revocable key.
**Findings (2026-10-07):** F-11 (SEBI primary text: OAuth-only, two-factor API access, vendor-client-specific API key and
whitelisted static IP, kill switch) and F-12 (NSE: one static IP per client, family excepted; API sessions logged out
daily). Both open for owner decision with Q258.
