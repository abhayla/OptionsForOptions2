# REQ-119: Stale replies dropped in the builder

Why: when the user moves a strike twice quickly, the first reply can arrive last and overwrite the second, so the screen
shows a max loss for strikes no longer chosen (register MR-142; Sensibull drops such replies).

Example: the user moves the short strike 24500 -> 24600 -> 24700. The reply for 24600 arrives after the one for 24700 and
is dropped; the screen keeps the 24700 numbers.

Technical decision (orchestrator, master register 2026-10-21, TECH direction).

Decisions: ADR-008 (one engine owns every number; the screen must show the engine's current answer).
