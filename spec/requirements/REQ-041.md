# REQ-041: Rule engine: entry, exit and rule defaults

One rule engine powers entry, adjustment and exit conditions.

Decisions: ADR-009. Sources: M §14, §15; C-file (real Q numbers: spec/traceability/question-register.md); H1 §13, §14; H2 §15; Q57.

**Open:** Rule priority, conflict and cooldown: open (§95). See `spec/open-questions.md`.

## Decision: evaluating a rule when some data is missing or stale (2026-09-29, owner delegation ADR-045)

Spec basis: ADR-015 (never use stale data as live; a trigger during a gap is not claimed), REQ-049 AC-3 (important
rules are never triggered silently from stale data). Recorded in the W-013 fix round after the independent verifier's
logic question.

- An input that is missing, or whose data health is not `available`, is **unknown**; a comparison on it is unknown.
- Rules use three-valued (Kleene) logic. **OR** is Triggered if any branch is proven true, Not triggered only if every
  branch is proven false, otherwise Cannot evaluate. **AND** is Not triggered if any branch is proven false,
  Triggered only if every branch is proven true, otherwise Cannot evaluate.
- A trigger reports only the proven values that decided it; the trigger record also lists every input the rule reads
  that was unknown. Example: exit "max loss 5,000 OR NIFTY ≤ 22,800" with live P&L unavailable and NIFTY at 22,700 is
  Triggered on the level; with NIFTY at 22,900 it is Cannot evaluate, never Not triggered.
- Premium inputs are the engine's net premium in rupees (`spec/business-rules/scenario-calculations.md` §3).
