# REQ-126: Monitoring, backups and environment separation

Why: the 2026-10-21 research found no error tracking, no uptime alert, no backup and no restore drill (register row
MR-141). A backup that was never restored is not a backup; the drill (AC-5) is what proves it.

Example: at 10:05 the API process crashes after a release. The tracker shows the new error group with the release sha
(AC-1), the uptime check fails twice and the owner gets one WhatsApp alert at 10:15 (AC-2), and if the release damaged
data, the 02:00 backup restores in the drilled time (AC-4, AC-5).

ADR-156 (2) puts error tracking in now; product analytics and session replay wait for consent (REQ-130). Hosting
itself is deferred (MR-140; ADR-054 stands).

Decisions: ADR-156, ADR-028, ADR-078.
