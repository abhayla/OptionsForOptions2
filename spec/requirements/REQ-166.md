# REQ-166: Calculation speeds and the safety valve

Why: the server should do the most work where people are looking and the least where nobody is. Example: 10,000 users
hold strategies, but at 11:00 only 800 have a screen open. The 800 open screens get their full table every second; the
other 9,200 strategies only add up a few shared numbers per check ("is delta above 0.30?", "is the loss above
Rs 5,000?"), which is far cheaper; drafts nobody has open cost nothing.

The reference product re-posts its builder every 30 seconds (REQ-135, ADR-213). Our default stays once a second
because prices are pushed live; the settings let us slow down without a code change if a machine cannot keep up.
