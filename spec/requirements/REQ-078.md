- id: AC-1
  text: >-
    Core proof first, before any screen work: on the owner's live session, a NIFTY iron condor built from real listed
    strikes is moved once each by Shift +1, Width +1 and Hedge +1 through the server function; each result is checked by
    hand against that day's strike list, the engine's max loss after each move is checked by hand to the paisa, and 50
    consecutive edits are timed on the development server with the 95th-percentile reply at or under 1,000 ms. The run
    is recorded as evidence; if any check fails, the build stops and is re-planned.
- id: AC-2
  text: >-
    The controls show when the strategy has at least 2 legs and at least one option leg. Shift works for any shape,
    Custom Strategy included; Width only for straddles, strangles, iron butterflies and iron condors; Hedge only for
    vertical spreads, iron butterflies and iron condors (the shape as REQ-076 AC-8 names it). A control that does not
    apply is disabled with its reason, for example "Width applies to straddles, strangles, iron butterflies and iron
    condors."
- id: AC-3
  text: >-
    Shift +1 / -1 moves every option leg by one strike step of the underlying (the strike gap read from the instrument
    file for that expiry: NIFTY 50, SENSEX 100 on 2026-10-21); futures legs do not move. The control shows the total
    moved since the user's last manual strike edit. Example (ADR-150): a NIFTY 22,800 / 23,000 bull call spread, Shift
    +1, becomes 22,850 / 23,050, showing "+50".
- id: AC-4
  text: >-
    Width +1 / -1 changes the distance between the highest short put and the lowest short call by two strike steps:
    every call leg moves up one step and every put leg moves down one step (reversed for -1), so hedge distances stay
    the same; the width never goes below 0. If half the change is less than one step, only the side nearer spot moves.
    Example: a NIFTY iron condor 22,600 / 22,800 PE and 23,200 / 23,400 CE (width 400), Width +1, becomes 22,550 /
    22,750 PE and 23,250 / 23,450 CE (width 500).
- id: AC-5
  text: >-
    Hedge +1 / -1 moves only the legs marked Hedge (REQ-076 AC-8) one strike step away from or towards their short
    leg; the minimum distance is one step; it needs an even number of legs, at most 4. Example: the condor 22,600 /
    22,800 PE and 23,200 / 23,400 CE (hedge 200), Hedge +1, becomes 22,550 / 22,800 PE and 23,200 / 23,450 CE (hedge
    250). When the put-side and call-side hedges differ (ADR-186, as in Sensibull), +1 moves only the nearer hedge out
    to the farther one's distance and -1 moves only the farther hedge in to the nearer one's; example: put hedge 300,
    call hedge 200, Hedge +1 -> call hedge 300, puts untouched.
- id: AC-6
  text: >-
    The browser sends only the control and its direction (for example "Width +1"); the server computes the new strikes
    from the listed strikes and returns the new legs with the engine's numbers (ADR-008). If any moved leg would land on
    a strike that is not listed or not eligible, the whole move is refused and nothing changes, with the reason naming
    the leg, for example "No 22,350 PE is listed for 27 Oct."
- id: AC-7
  text: >-
    A move only changes strikes the user already chose: it never adds or removes a leg and never changes a side, lots,
    expiry or option type, and it happens only on the user's click (ADR-150 (1)); nothing moves by itself.
- id: AC-8
  text: >-
    Every moved leg is a new contract and gets a newly captured planned entry with the move time (ADR-068 (1)); legs
    not moved keep theirs. A leg that had a typed price (REQ-077) loses it on a move and the screen says so, for example
    "Your price for leg 2 was replaced by the captured price of 23,050 CE."
- id: AC-9
  text: >-
    A manual strike edit (stepper or picker), a Width click or a Hedge click resets the Shift total, shown as "-"
    (ADR-186 (2), as in Sensibull). A click writes no history entry of its own; the history (REQ-070) records the
    result when the strategy is saved (ADR-186 (3), as in Sensibull).
- id: AC-10
  text: >-
    Without live data the moves still work on strikes and the numbers follow REQ-077 AC-9. When today's instrument file
    is not loaded (ADR-104), the three controls are disabled with the reason, never computed from yesterday's list.

# REQ-078: Shift, Width and Hedge

Why: once a user has a shape, the most common next step is "the same thing, a bit higher", "wider", or "cheaper
wings". Sensibull does this in one click per step (study 2026-10-21). The owner allowed it now because it only moves
strikes the user already chose (ADR-150 (1)). Unlike Sensibull, which computes the moves in the browser, OFO2
computes them on the server from the real strike list (ADR-008), so a move never lands on a strike that does not
exist.

Register: MR-008 (WRITE under ADR-150 (1)), MR-078 (TECH core proof: AC-1 is it; the latency target is a technical
call recorded here).

Decisions: ADR-150, ADR-055, ADR-008, ADR-068.
