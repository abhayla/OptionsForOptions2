# REQ-058: Partial execution and no automatic retry

A partly executed strategy becomes an explicit exception; the user decides; V1 never retries on its own.

Decisions: ADR-017. Sources: M §47, §48; C-file (real Q numbers: spec/traceability/question-register.md); H1 §22; H2 §22.

## Owner decision (2026-09-29, Q223): open entry orders during Close Partial Strategy
- When the user picks Close Partial Strategy while one of the strategy's own entry orders is still open at Zerodha,
  the Close preparation also lists a CANCEL request for each such order, shown with the exit orders and confirmed by
  the user in the same step. Nothing is sent without that confirmation. Why: an entry order that fills after the
  exits would leave a position the user believes closed (e.g. a naked short call).
- **Clarification (owner, 2026-10-15, ADR-079):** under ADR-054 the platform sends no order, so the CANCEL request is an
  instruction to cancel that order in Kite (with a link to Kite's order book); the exit basket is offered once Zerodha
  shows the entry order Cancelled or filled.

## Owner decision (2026-10-18, ADR-109): a partly filled exit
- AC-2's four choices apply to a partly filled ENTRY. A partly filled EXIT offers two: "Complete exit" (a new basket
  for the remaining quantity, priced fresh from depth, ADR-079) and "Review manually". Example: an exit of 130 (2
  lots) fills 65 -> "Complete exit" prepares a basket for the other 65. Reason given with the recommendation the owner
  chose (orchestrator's, not the owner's words): on an exit, Retry and Close Partial would place the same remaining
  basket, and two buttons doing the same thing invite a double press.

## Owner decision (2026-09-29, Q238): order of exit orders
- When the platform closes or completes a multi-leg strategy, it **buys back the short legs first, then sells the long
  legs**, and never mixes the two in one batch (was orchestrator default OD-e in `backend/ofo/execution/partial.py`).
  Example, closing an Iron Condor: step 1 buys back the 23,000 PE and 23,400 CE; step 2 sells the 22,800 PE and 23,600
  CE. Why: if the long wings were sold first and a buy-back then failed, the user would hold naked shorts (unlimited
  risk); the other order only leaves extra long options for a moment (limited risk). Mirrors "protective legs first"
  on entry (REQ-056, W-022).

## Owner decision (2026-10-20, ADR-136): partial entry actions (SPEC CHANGE to AC-2)
- AC-2's four entry choices (Complete Strategy / Retry Failed Leg / Review Manually / Close Partial Strategy) are
  replaced by: "Check with Zerodha"; "Place missing legs" (our basket, whole lots, each sell at most what its buy filled,
  priced fresh, only when Zerodha's margin covers it, no open order on that contract at Zerodha, market hours, never
  split, never while a reconciliation block is up); "Close filled legs" (cancel any still-open entry order on Kite first,
  Q223; then buy back shorts, check, then sell longs, Q238); "I'll manage it on Kite"; and a "Change price on Kite" link
  while an order is open. The app never edits or cancels an order (ADR-100, ADR-079) and never builds a second order for
  a leg that is still open. Margin short: only Close filled legs or keep, no basket (REQ-055 AC-4). Each choice shows its
  worst-case loss; after 15:30 IST the screen says the position is carried overnight. Exits keep ADR-109 (3).
- Example: Iron Condor (NIFTY 65), buys and the 23,000 PE sell filled, the 23,400 CE sell rejected for margin -> Close
  filled legs buys back the 23,000 PE first, then sells the 22,800 PE and 23,600 CE.
