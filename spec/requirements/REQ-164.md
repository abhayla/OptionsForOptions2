# REQ-164: Several API copies, no single-copy memory

Why: today one API copy serves everything, and some state lives only in its memory. Example: 1,000 users log in to
Zerodha between 09:05 and 09:15. The login code is held in one copy's memory and only 20 can be in progress at once, so
most are refused; and if that one copy crashes at 10:30, every user is cut off until it restarts.

What is not in scope: buying more servers (a deploy decision), and the shared licensed price feed (REQ-048 AC-4,
REQ-052, ADR-170: a business decision that waits for Zerodha or a vendor).

Decisions: approved by the owner 2026-10-31 ("Go with your recommendation"); order per docs/process/multi-user-foundation-plan-2026-10-31.md (right after GC-ADJ2). AC-7 added 2026-10-31 by ADR-220 (owner: role names, one machine first, separate as users grow).
