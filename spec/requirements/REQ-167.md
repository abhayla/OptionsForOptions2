acceptance_criteria:
- id: AC-1
  text: >-
    A settings registry (a data file) lists every setting: key, group, label, unit, type, allowed range, default and a
    one-line "what it changes". The store keeps each change as a new dated row (append-only, like the charge rates of
    ADR-082); the value in force at a time is the newest row not after that time, else the default.
- id: AC-2
  text: >-
    The Settings page shows the settings by group with the value in force, the default, when it took effect and who
    set it, and the history of earlier values. The admin changes a value with an effective time (now by default); a
    value outside the allowed range or of the wrong unit is refused with the reason (e.g. 6.5 typed for a rate whose
    unit is a fraction: "Enter 0.065 for 6.5%"). Reset to default is a new row, never a delete.
- id: AC-3
  text: >-
    Only the admin can change a setting; every change is written to the audit log. Until sign-in exists the admin is the
    single owner; every settings write passes one guard that becomes the admin role check when sign-in lands.
- id: AC-4
  text: >-
    Each wired calculation reads the value in force when it runs (no restart): changing a setting changes the next
    figure, alert or choice, and a test proves it for each wired setting.

    rate set is added from the page with its source URL.

  text: >-
    A guard test fails when a module wired to settings holds a business literal again, and when a registry key has no
    reader.

# REQ-167: Admin Settings page

Built in phases (docs/design/settings-scan-2026-10-31.md): phase 1 the store, the page, the Charges group and three
wired values (risk-free rate, near-level alert distance, cost per leg); later phases move the remaining groups as
listed in the scan. The Undo window default waits for the owner (F-79).
