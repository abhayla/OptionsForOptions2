# REQ-049: Normalized market data and data health

Every quote is normalised to one internal model and carries a health state.

Decisions: ADR-012, ADR-015. Sources: M §40; C-file (real Q numbers: spec/traceability/question-register.md); H2 §5.

**Clarification (orchestrator, 2026-10-15, spec reading - no new decision):** AC-5's message applies only "when live
data drops", i.e. after a quote for the strategy was held; its time is the newest quote held, never the time of the
request. When no quote was ever held for any of the strategy's inputs, there is nothing to have dropped and no time to
show, so the label is ADR-020 Q185's draft label ("Draft — Live data not connected"), which ADR-068's consequences
already assign to the no-live-data case. Found by the W-065 Tier A verifier (a not-live answer stamped "Last updated"
with the request time when no price had arrived); built in W-065 round 2.

**Owner decision (2026-10-15, ADR-077):** when the browser's own live connection drops, the fallback also shows AC-5's
message with the newest price time the strategy received; the platform keeps each contract's last price time (never
the price) after its subscription ends. The draft label stays only for a strategy that never received a price.

**Open:** Staleness thresholds are an implementation setting. See `spec/open-questions.md`.

**Findings (spec/findings.md, 2026-10-07):** F-29 - the first real Kite replies: times arrive without a timezone (the
adapter attaches IST), bid/ask exist only in `depth` and read 0 when the market is closed (0 maps to absent, never a
Rs 0 price), and there is no OI-change field. Raw replies: `docs/research/kite-proof-2026-10-07/`.

**Findings (2026-10-08):** F-32 - on a live feed a median 59 of 1,091 contracts had no tick for over 60 s while the
feed was healthy (Kite sends only changes), so staleness by a contract's own age misflags quiet contracts (AC-2; open
for the data-path work item; registry `staleness-by-last-change-age`). F-33 - Kite sends money as binary floats
(`291444.67000000004`), so the adapter parses JSON numbers as Decimal from their text (AC-1; registry
`money-parsed-through-float`).
