    never an old price as live (ADR-015).
- id: AC-3
  text: >-
    While there is one process, no bus or Redis is added. Once the market-data process and the API process both run, the
    internal bus (Redis per ADR-043) carries ticks and order events between them; the bus holds no state that cannot be
    rebuilt. After a bus loss, every consumer marks its data stale (ADR-015) until a fresh tick or a fresh Zerodha read
    arrives.
- id: AC-4
  text: >-
    PostgreSQL is the only durable record of plans, orders, fills, triggers and strategies; nothing is decided from a bus
    message alone. An order event from the stream starts a reconciliation read (REQ-060 AC-1), never a position change
    by itself (REQ-057 AC-2).

  text: >-
    Each user's data stays that user's (ADR-053): ticks and order events carry the user they belong to, and a test shows
    that user A's order event or quote never reaches user B's browser. Market-wide calculations on identical data still
    run once per snapshot (REQ-050).
- id: AC-6
  text: >-
    The market-data process respects Kite's per-connection instrument cap and per-key connection cap as Zerodha states
    them at build (held as configuration with source and date, never typed from memory); a subscription beyond the cap is

- id: AC-7
  text: >-
    The process holds Kite tokens only in memory, loaded from the encrypted token store (REQ-015); every Kite call it
    makes goes through the egress gate (REQ-073 AC-4, ADR-098), like the API process.

  text: >-
    At the daily 06:00 session expiry (ADR-053) the process closes that user's sockets, publishes "session ended" for

# REQ-113: Feed process separate from the API

Why: with each user's own Kite feed (ADR-053), 200 users means 200 sockets. Inside the API process every deploy would cut
them all mid-session; users would see prices freeze and monitoring pause on every release (register MR-061).

Example: a fix to the Orders page is deployed at 11:30. The API restarts; the market-data process keeps all users' Kite
sockets open; browsers show "reconnecting" for about 3 s and resume with fresh prices.

Technical decision (orchestrator, master register 2026-10-21, TECH rows MR-061 and MR-062): separate process; bus only
with two or more processes; PostgreSQL the durable truth.

Decisions: ADR-012, ADR-043, ADR-053.
