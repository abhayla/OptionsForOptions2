# REQ-054: Broker adapter

Zerodha is reached through a minimal broker adapter.

Decisions: ADR-016, ADR-050 (AC-3, AC-4 added 2026-10-02). Sources: M §76; C-file (real Q numbers:
spec/traceability/question-register.md); H1 §8.

## Exchange segment vocabulary (AC-3; F-10, 2026-10-02)
"Exchange segment" in AC-3 is the exchange's market segment, from one fixed list owned by this platform, never a
broker's column copied as is. V1 values: `NSE_FO` (NSE futures and options) and `BSE_FO` (BSE futures and options).
Zerodha mapping: `exchange` NFO -> `NSE_FO`, BFO -> `BSE_FO`; any other row is outside V1 and is not loaded. Index and
cash segments (`NSE_INDEX`, `BSE_INDEX`, `NSE_EQ`, `BSE_EQ`) are added only when a requirement needs them, because
Zerodha's `exchange` = NSE covers both index and cash rows and their numbers collide (NSE / 1001 = NIFTY 50 and
94SFL28-YL). A contract's identity is (exchange segment, exchange token).

## Per-broker values and their date (AC-4; W-056 review, 2026-10-02)
- The date stored with a broker's lot size, tick size and freeze limit is the day the platform loaded that broker's
  list, taken from the database clock (ADR-023), never a date supplied by the caller.
- A broker list that does not carry a value leaves the stored value unchanged: Zerodha's list has no freeze limit, so
  loading it never clears or overwrites a freeze limit stored from another source.

## Findings this requirement rests on (spec/findings.md)
- F-01 (exchange token shared by all brokers), F-02 (Zerodha's instrument_token is not), F-03 (symbols differ and are not
  unique), F-04 (scales and limits differ per broker), F-08 (plugin-per-broker reference design, licence unchecked),
  F-06 (SEBI static IP and algo ID affect the adapter; open for owner decision, Q258), F-10 (Zerodha's `exchange`
  column is not an exchange segment), F-11 and F-12 (SEBI and NSE primary text on API keys, static IP per client and
  daily session logout; open for owner decision, Q258).
