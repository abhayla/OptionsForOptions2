id: REQ-168
title: Each user sets their own adjustment preferences on a Preferences tab of the Adjustments screen, starting from the admin's defaults
statement: >-
  The Adjustments screen has a Preferences tab where a user sets the adjustment values that apply to all of their
  strategies. A value the user has not changed follows the admin's default in force; a value the user changed is
  theirs until they reset it. Stage-by-stage numbers stay in the user's playbooks; no value is held in both places.
source: >-
  Owner, 2026-10-31 (chat): "adjustment related preferences should be in the adjustment screen in a separate tab ...
  each user will have their own preferences for adjustment, so that should be at user level"; question tool answers
  Q1 "Prefs tab + playbooks", Q2 "Admin sets defaults", Q3 "Remove it" (Rs 40 per leg), Q4 "Right away, plans kept".
  Decision row ADR-222 (5)-(9), (11).

  A preference read for the wrong user changes another user's alerts and approach strikes; a value held both in a
  preference and in a playbook gives two answers to one question.

acceptance_criteria:
- id: AC-1
  text: >-
    The preferences are: the short-strike delta an approach picks strikes at (weekly 0.30, monthly 0.25 today,
    ofo/adjustment/approach_config.json); the roll distances (200 / 500 points) and the other approach_config.json
    values (iron fly only with 3 or more days left; reduce divisor 2); the alert distance for a strategy with no playbook
    (0.5% today, ofo/adjustment/detection.py:32); the gap-at-open window (until 09:30, ofo/adjustment/playbook_eval.py:41);
    the Compare chart range, steps and move columns (+/-6%, 48, +/-1% and +/-2%, ofo/adjustment/compare.py:87-89).
    There is no cost allowance per leg (ADR-222 (8)).
- id: AC-2
  text: >-
    Each preference shows its value, "Your value" or "Default" and the admin default; the user changes it within the
    allowed range (refused with the reason otherwise) or resets it to follow the default. History of the user's own
    changes is kept.
- id: AC-3
  text: >-
    A user reads and changes only their own preferences. Until sign-in exists there is one user (the owner); every read
    and write is keyed by the user and passes one guard that becomes the per-user check when sign-in lands.
- id: AC-4
  text: >-
    A change applies at the next check to every one of that user's tracked strategies and to the next Compare; a saved
    plan is not changed; every alert line names the value it used.
- id: AC-5
  text: >-
    The starting value of each preference is the admin's "Adjustment defaults" group (REQ-167 AC-5); when the admin
    changes a default, users who did not set their own value follow it at the next check.
