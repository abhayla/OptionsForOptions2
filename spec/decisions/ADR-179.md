# ADR-179: User reads after a 429 fail fast; background reads retry

Why: waiting 10 s or more inside a user's Execute or Positions request would hang the screen with no feedback, and
retrying inside Kite's cooldown extends the block for every user of the app key (F-60). A clear "busy" at once, with the
limiter holding further sends until the cooldown ends, serves the user and protects the key.
