# ADR-052: Identity includes the expiry date

## Evidence
- F-21: in 45 NSE F&O daily files (3 Aug - 6 Oct 2026) 4,768 of 65,265 contract numbers mapped to more than one
  contract, e.g. 67245 = ABCAPITAL 25-Aug-2026 410 PE, then NIFTYNXT50 29-Dec-2026 72200 PE; 421 touch NIFTY. No two
  contracts shared a number on the same day. Zerodha's docs: "Exchanges may reuse instrument tokens for different
  derivative instruments after each expiry".
- A live contract's strike can change under the same number (NSE 79199 HINDPETRO 410 -> 390.75, 14 Aug 2026).

## Why the expiry, not a validity range
- Every broker file and the exchange file carry the expiry, so the key stays broker-neutral (F-01) and is known the
  moment a contract appears; a first-seen/last-seen range would depend on when our loader ran.
- Two live contracts never share (segment, token) on one day, and a reused token always belongs to a later expiry, so
  adding the expiry is sufficient.

## Alternatives not taken
- A validity date range per token (harder to query; depends on load timing).
- Keep (segment, token) (a saved strategy could later resolve to another contract).
