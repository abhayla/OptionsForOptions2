# ADR-007: Option Chain

## Owner answers
| Q | Rule |
|---|---|
| Q34 (T1 #119) | Option B + owner detail: from the Builder the user opens the chain, ticks contracts (checkboxes on the **Calls side (left)** and **Puts side (right)**), and clicks **Add Selected (N)**; all ticked contracts arrive in the Builder as legs. |
| Q35 = C (#121) | Buy/Sell can be set in the chain **and** in the Builder; the **Builder is the default place**. |
| Q36 = D (#123) | Quantity in **lots**; exact quantity only in Advanced; current lot size always from contract data. |
| Q37 = B (#125) | The chain may set Action + Lots; the Builder stays the authoritative place where the whole strategy is reviewed. |
| Q38 = D (#127) | Filters adapt to UX level — Guided: expiry, strike range, ITM/ATM/OTM; Standard: + premium, Delta, IV, OI/volume; Advanced: all, incl. bid/ask, Greeks, liquidity. |
| Q39 = C (#129) | The Builder sets the strategy expiry; the chain can browse another expiry and import from it; expiry is shown on every leg. |
| Q41 = B (#133) | Mixed expiries in a selection → *"Multiple expiries detected … Continue / Review Selection"*. |
| Q42 = B (#135) | The same contract selected twice **within one selection** is combined into one row (same underlying, type, expiry, strike, contract **and action**: T1 #136's example is Buy + Buy → *Buy 23,000 PE × 2 lots*; a Buy and a Sell of the same contract are never merged, Q43 = B, T1 #143). |
| Q43 = B (#143) | Same contract with opposite actions = two separate legs; no netting; engine may flag it as redundant. |
| Q44 = D (#145) | An unavailable contract stays visible, marked unavailable; Zerodha-valid alternatives may be shown; the user picks; never silently replaced. |
| Q45 = A (#147) | Clean default columns **LTP · Change · IV · OI · Volume | Strike | …**; *Advanced Details* adds Bid, Ask, Delta, Gamma, Theta, Vega, OI Change. ATM strike highlighted; underlying price shown; expiry selector on top; calls left, puts right; selected contracts highlighted. |
| Q46 = C (#149) | LTP/bid/ask stream; OI, IV and derived values refresh less often. |
| Q47 = B (#151) | A persistent *Selected Legs* summary while scrolling, then *Add to Strategy*. |
| Q48 = C (#153) | Selecting a contract **already in the strategy** asks: *Increase existing leg · Keep as separate leg · Cancel*. |
| Q49 = B (#155) | Validate before import: blocking errors (e.g. contract unavailable) vs warnings (e.g. mixed expiries). Checks run (T1 #154): duplicate contracts, same contract with opposite actions, mixed expiries, invalid/unavailable contracts, invalid lot quantities, contracts Zerodha currently doesn't permit, obvious strategy-construction conflicts. A blocking error blocks **only that leg until it is resolved** (T1 #154 "should block that particular leg until resolved"); "genuine execution/contract problems must be resolved first", legitimate combinations pass with a warning (T1 #156). |
| Q50 = B (#157) | Selections persist across expiry tabs. |
| Q51 = A (#159) | Recognise templates (*"Looks like an Iron Condor"*); never auto-convert or execute. |
| Q53 = A (#163) | **Buy / Sell buttons on each contract** row; action never inferred. |
| Q54 = A (#165) | `− N lots +` stepper respecting the valid lot size. |
| Q55 = A (#167) | Compact live preview: net credit/debit, max profit, max loss, breakevens, mini payoff; full analysis stays in the Builder. |
| Q56 = D (#169) | Remove immediately with a short *Undo* (duration open; ChatGPT suggested ~5 s, never answered). |

Owner (T1 #69, see ADR-016): contracts Zerodha will not accept for the intended order **cannot be added** to a
strategy (*"27,000 CE — Currently unavailable on Zerodha ⚠️"*).
Access: live chain only for logged-in Pro users (ADR-023).
