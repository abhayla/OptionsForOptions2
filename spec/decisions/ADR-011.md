# ADR-011: Adjustment engine and platform-detected adjustment opportunities

## Decision
- Model (Q152): Strategy + Current Market + Time + P&L + Greeks + Position Geometry + User Rules → Trigger →
  Candidate Adjustment → Before/After → User Decision.
- Detection without user rules: **yes** (Q149). Always labelled as platform-detected vs *Your rule was triggered*
  (Q150). Never presented as a personalized instruction (§32).
- Triggers (Q154): underlying move/level, distance from short strike/BE, leg profit, strategy max profit/loss,
  Greeks, IV change/percentile, DTE, premium, P&L, compound AND/OR.
- Actions (Q155): take profit, close/roll leg, roll spread, move strike, add/remove hedge or leg, change quantity,
  re-center, convert strategy, exit, alert, no-trade proposal.
- Before/After for every proposal: legs, P&L, risk, margin, Greeks, breakevens, payoff (Q156).
- *Why am I seeing this?* explains exact condition, strike/BE, distance, metric/rule, timestamp, data state (Q157).
- No user rule → generic warning + generic approaches only (Q159).
- **Four-layer panel (Q160):** 1 Why detected · 2 Current strategy state (P&L, max P/L, BEs, net Δ/Γ/Θ/V, margin
  utilization, DTE, relevant IV/OI/LTP) · 3 Possible approaches, with no automatic recommendation · 4 Next step:
  user picks an approach → platform builds the configuration and shows Before/After → user decides.
- Adjustments can increase risk (Q158). Rule priority/conflict/cooldown: open (§95).
