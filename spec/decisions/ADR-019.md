# ADR-019: Strategy definition vs live state, versions, state machine, exceptions, timeline and trigger audit

## Decision
- **Definition vs live state** (Q189): see `spec/data/domain-model.md`. Never one mutable object.
- Versions preserved (Q190). **Proposed ≠ active** until user confirmation + successful execution/reconciliation;
  partial execution → exception state; broker actual state wins (Q191, §12).
- **State machine** (Q200): Draft · Ready for Validation · Validated · Active · Monitoring Paused · Adjustment
  Proposed · Execution in Progress · Partially Executed · Reconciliation Required · Completed · Exited · Archived.
  Transitions explicit; never inferred from order rows. The allowed transition table is not in the handoff and is
  drafted in `spec/data/domain-model.md` as a proposal.
- **Exception states** (Q201): what happened · timestamp · what is blocked · next action. No "something went wrong".
- **Timeline** (Q202): immutable, chronological, append-only: created, modified, validated, activated, rule
  triggered, adjustment proposed, order prepared/submitted/filled, partial execution, rejection, reconciliation
  required, external broker change, user acknowledgement, exit, completion.
- **Trigger audit** (Q203, §97): which rule; exact input values; threshold; timestamp; market-data source; fresh or
  healthy; active version; what the system did next; alert generated?; order prepared?; confirmation required?;
  executed?; what the broker reported; reconciliation succeeded?
