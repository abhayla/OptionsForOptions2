title: When a changed row is a revision and when it is a new contract; delisting heals itself; a second per-expiry guard
decision: For a list row whose token is held by a live stored contract, the change is a revision of that contract only
  if the underlying, option type and exchange segment are unchanged AND either (a) the strike is unchanged and the
  expiry moved by at most 7 calendar days, or (b) the expiry is unchanged and the strike changed. Any other change -
  another underlying or type, both strike and expiry changed, or an expiry moved by more than 7 days - means the
  exchange reused the token, so the stored contract is delisted and the row becomes a new contract. A delisted contract
  that comes back with the same token, underlying, type, strike and expiry is reinstated as the same contract (its
  internal id kept), so a partial download never orphans a strategy. Besides ADR-058's per-index 10% guard, a daily
  update is refused, writing nothing, if any one unexpired expiry of an index would lose more than half of its live
  contracts at once. A list row whose expiry is already before the load date is skipped, never loaded.

# ADR-059: Revision or new contract

## The real cases this rule must classify
| Token | Change | Kind |
|---|---|---|
| 62964 | NIFTY 31000 PE expiry 26-Mar-2026 -> 31-Mar-2026 (5 days, same strike) | revision |
| 61746 | NIFTY 23000 CE expiry 27-Dec-2029 -> 24-Dec-2029 (3 days, same strike) | revision |
| 79199 | HINDPETRO 29-Sep-2026 strike 410 -> 390.75 (same expiry) | revision (corporate action) |
| 67245 | ABCAPITAL 410 PE -> NIFTYNXT50 72200 PE (another underlying) | new contract |
| 61746 | NIFTY 23000 CE -> WIPRO futures (another underlying and type) | new contract |

## Why
The W-057 review showed that a token freed and reused within one daily list was never seen as a reuse: the old
contract's token was still in the list, so a NIFTY 23000 CE token reappearing as, say, a NIFTY 20550 CE of another month
would have been taken as a strike-and-expiry revision, and every strategy on the old contract re-pointed. The exchange's
own revisions seen in real data change one thing (expiry by a few days, or strike for a corporate action), never both.

Reinstating an identical returning contract makes a delisting reversible, so a list that briefly misses one expiry
(below the 10% index guard) heals on the next good list instead of creating new ids. The per-expiry half guard catches
a list missing most of one expiry at once.
