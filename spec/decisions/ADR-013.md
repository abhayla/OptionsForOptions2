# ADR-013: Historical data tiers, adjustment metric history and simulation priority

## Decision
- Tiers (Q110, Q168, §36): 1 real-time · 2 aggregated intraday (1m/5m) · 3 daily · 4 strategy snapshots.
- Build history from the live feed where practical **and licensed** (Q111, Q169). A separate historical provider
  plugs into the same abstraction (Q183).
- Adjustment metric history kept (Q161); leg + strategy data (Q162); underlying data alone can drive analysis (Q163);
  new metrics addable without redesign (Q164); collected even without user rules (Q165).
- **Data Feasibility Test** for every metric (Q166, §35): raw data? source? can we calculate it? scale impact?
  historical availability? legal/licensing? update frequency? storage? calculation method?
- Raw data first; derive metrics ourselves where practical (Q167).
- Historical data is lower priority and never blocks live creation, chain, execution or monitoring (Q112, Q177).
- Simulation: simple strategy simulation, EOD default, intraday later, clearly labelled; not a quant backtester (Q113, §72).
  Candidate metrics (15 Sep §16): best/worst outcome, winning days, drawdown, historical behaviour. Always labelled
  as historical behaviour, never a future guarantee.
