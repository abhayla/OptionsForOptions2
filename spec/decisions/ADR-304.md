title: 'A saved plan Target is acted on (any usable value); what the percent divides by is recorded as it stands; every screen limit comes from the rule check itself'
decision: >-
  Decided by the assistant on 2026-11-13 under the owner's standing rule that strategy calls are the assistant's, after an
  independent review. (1) A Target saved in a trade's plan is acted on: it switches the profit-target rule (T-07) ON for
  that trade even when the rule set has it off, exactly as the plan's Stop does for the stop rule (ADR-252). This holds
  for ANY usable saved Target (a number above 0 and up to 100), including one equal to the rule set's own value: the
  independent review on 13 Nov found the first build skipped the equal case (T-07 off, Target 50 saved, the sheet showed
  50, nothing acted). (2) What "% of max profit" is divided by is NOT changed by this run. As the code stands on 13 Nov:
  T-07 compares max(pnl, 0) x 100 with max_profit (playbook_eval.py:539-541, ratios.profit_pct_of_max_profit at
  adjust_ratios.py:50-51); pnl is the booked P&L plus the open legs at their current price, with no charges term
  (adjustment_check.py:336-337, adjust_money.pnl_now at adjust_money.py:70-73), so the numerator is before charges (ADR-294
  (1)); max_profit is read from the `gross` side of the priced position (adjustment_check.py:342, 366), which the code
  names gross, so the divisor is the before-charges max profit; the names were read, `price_after` itself was not
  traced on 13 Nov, so this stays to be confirmed when the after-charges figures reach the rule screens. (3) Every
  screen line that states a limit a rule acts on (the plan card, the alert text, the rules line) reads the limit the rule
  check itself computed for that moment, never a second calculation. Why: the plan card went wrong twice on 13 Nov: first
  it showed Target 50 / Stop 50 while the last day acts at 80 / 40; then expiry-day tightening and the 2x-credit stop were
  missing from it. Decision support only (ADR-003).

# ADR-304: the plan Target acts; limits on screen are the rule check's own

Why: two review rounds fixed the card by recalculating limits beside the rule check, and the card went wrong twice. One
source (the rule check's own limit) removes the second calculation that kept drifting.
