# ADR-058: Delisting before expiry, and a counting guard

## Evidence (F-30)
Token 61746 was NIFTY 23000 CE expiring in Dec 2029; from 26 Aug 2026 it is WIPRO Nov-2026 futures, and Zerodha's list
on 7 Oct 2026 carries NIFTY Dec-2029 calls only at 15000, 16500, 18000 ... (1,500 points apart) - no 23000 CE. The
contract left the market more than three years before its expiry.

## Why a count and not "any removal"
- Q244 was written for one failure: a truncated file that cut an index by 40% (issue #10 item 2). A count threshold
  still refuses that file.
- Under "any removal", one real exchange clean-up of a long-dated strike would make every later daily list refuse,
  freezing the catalogue - the failure Q257 was written to avoid.
- 10% is far below the 40% failure and well above a strike-grid clean-up (one long-dated expiry's strikes are a few
  percent of an index's ~1,800-3,000 live contracts, F-29 counts). It is an admin setting because the right value is
  learned from real days.

## Example
Day N: NIFTY has 1,832 live contracts. Day N+1's list lacks 14 Dec-2029 calls and adds 13 new ones: 14 / 1,832 = 0.8%
-> accepted; the 14 are marked delisted. Day N+2's list is truncated and lacks 740 NIFTY contracts: 40% -> refused,
nothing written, an alert raised.
