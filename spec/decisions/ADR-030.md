# ADR-030: Delivery approach: prove data first, core first, verify, then parallel worktrees

## Owner statements
- T1 #175: data is the **first goal**; everything else after.
- T2 #131: implement in Claude Code; **core first**, verified, then **parallel worktrees** for other features.

## Plan (implementation-control file + M §92)
Discovery → prove the data/Zerodha core on real input → core domain + calculations (invariants as tests) → one slice:
Create Strategy → Configure Legs → Calculate → Save Draft → Connect Zerodha → Validate → Prepare Execution Plan →
Review → Execute → Confirm Broker Execution → Reconcile → Active Monitoring → verification gate (domain,
calculations, broker, execution, reconciliation, UI screenshots) → bounded parallel work that never redefines core
semantics. Definition of done and failure tests: `spec/testing/core-invariants.md`. Production: prepare, test,
validate, release notes, plan — then stop for the owner.

Phase-0 data tests (T1 #176): live ticks reliably; full chain rebuilt; own Greeks; stale/missing detection;
reconnect survival; enough history persisted; 100/1,000 users on one normalised feed; licence permits the use.
