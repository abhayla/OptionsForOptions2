# ADR-030: Implementation approach: discover, core domain, one vertical slice, verification gate, then parallel

## Decision
- Phases per the handoff §92 and the implementation control §3–§8. Do not build every screen before the slice works.
- Verification gate (control §7): domain (versioning, transitions, rules, timeline), calculations (payoff, P&L,
  BEs, max P/L, scenario table), broker (connection, margin, submission, status, positions), execution
  (dependencies, partial, no auto-retry, no silent unwind), reconciliation (mismatch, external change, manual,
  block), UI (screenshots, responsive, strategy-only controls, error states).
- Parallel work (control §8, §9): one bounded domain per worktree; never redefine Strategy semantics, execution
  invariants, state machine, formulas or reconciliation authority.
- Failure tests required (control §11) and UI screenshot verification (control §12): `spec/testing/core-invariants.md`.
- Definition of done (control §21): implemented; tests pass; failure cases tested; invariants intact; UI
  screenshot-verified; no locked decision violated; docs/status updated; reviewable; no accidental production change.
- Production (handoff §99, control §20): prepare, test, validate, release notes, deployment plan — then **stop** for
  the owner's explicit authorization. Matches `.claude/rules/kit/deployment.md`.
- Engineering principles §88 (20 items) apply as written.

## How this fits the kit (no conflict found, one ordering note)
- The kit's "prove the core first" rule puts a **real-input core proof before Phase 1**: the thinnest real run
  showing Zerodha login → live NIFTY/SENSEX option quotes → margin check works (see HANDOVER NEXT). The handoff's
  Phase 0 already says "inspect before building"; the core proof is its first step.
- The legacy repo `abhayla/OptionsForOptions` stays read-only reference (OD-29); reusable engineering capabilities
  go to the Factory as `harvest` issues, not edits here.
