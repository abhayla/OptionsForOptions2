# ADR-008: Calculation engine, scenario formulas and the single strategy table

## Decision
- **One engine** for every P&L/payoff/scenario number (Q115). Formulas are never duplicated in components.
- Every user, beginners included, sees the outcome view before execution: P&L, max profit/loss, breakevens,
  payoff, scenario behaviour, margin, risk (Q114, §22).
- **Expiry formulas (Q116)** and scenario rules: `spec/business-rules/scenario-calculations.md`.
- Live P&L uses current market price; expiry scenario uses entry price + intrinsic value (Q117).
- **One table**, locked column order, sticky left columns, current level highlighted (Q118, §23).
- Every scenario cell filled for every leg — no blanks (Q119).
- Scenario levels ~100 points apart around the current level, ~1,000–2,000 points of range, configurable (Q120).
- Breakevens are strategy-level only (Q121).
- Live first-class fields: Entry Price, LTP, Entry Value, Current Value, Unrealized P&L, P&L % (Q122).
- Greeks IV, Delta, Gamma, Theta, Vega sit after P&L % and before scenario columns (Q123). Platform computes Greeks
  itself where feasible; vendor Greeks are reference only (§27).
- Established libraries/formulas may be used for Black-Scholes, IV and Greeks; product logic stays in the platform.
  Avoid false precision (§21).

## Gaps
- **Q33A is still unanswered** (15 Sep handoff §38): should scenario columns show expiry P&L, estimated current

  comprehensive handoff lists "exact current-vs-expiry P&L model" as open. Until decided, scenario columns show
  **expiry P&L only** (the only locked formulas). See `spec/open-questions.md` Q33A.
- Scenario anchoring (exact spot vs rounded ₹100 centre) is not decided (15 Sep §37 item 3).
