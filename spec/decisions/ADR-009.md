# ADR-009: Rules engine, entry/exit rules and V1 automation (Alert + Prepare Orders)

## Owner answers
- **Q1 = A** (T1 #3): assisted first; architecture allows controlled automation later.
- **Q5 = B** (T1 #11): **Alert + Prepare Orders** — condition met → alert → exact multi-leg orders prepared → user
  reviews → user executes. Future levels (authorised auto-entry, autonomous management) are not V1.
- **Q17 = D** (T1 #35): simple entry conditions — *Enter now* (default), market reaches range, premium target (*Wait for
  better premium*), volatility, time window — plus an advanced compound rule builder hidden unless asked.
- **Q18 = D** (T1 #37): simple exit conditions in V1 (profit target, max loss, time, underlying level; action = alert or
  prepare exit orders), compound later.
- **Q151 / Q152** (owner, T2 #87): exit and adjustment rules are defined **inside the strategy** while building it; the
  plan is made "while the brain is calm".
- **Q153 = C** (owner, T2 #89): exit and adjustment plans are **both optional**. This **supersedes** "every strategy
  has an explicit exit plan" (Q18 recommendation, T1 #38) and the Q32 note that Advanced cannot execute without an exit
  plan.

## ChatGPT (delegated, T2 #86–#90)
- Q140: after configuring legs, the next Builder step is Entry + Adjustment + Exit rules.
- Q141: guided, not blocking; the platform explains the consequence of a missing rule.
- Q142/Q143: it suggests rules for the strategy (profit target, max loss, level reached, short strike threatened,
  time exit); a suggestion is never active until the user confirms it.
- Q144: default rule templates — Exit: profit target, max loss, expiry/time, underlying level. Adjustment: level
  reached, short strike threatened, P&L threshold, DTE threshold. Entry: now, level, premium, volatility, time window.
- Q145: same engine, UI adapts to UX level (*"Adjust when NIFTY moves above ___"* vs *"Underlying ≥ X AND delta ≥ Y
  AND IV percentile ≥ Z"*). Q146: AND/OR supported. Q147: controlled complexity in V1.
- Q148: on trigger — explain the trigger, show the defined action and Before/After; the user decides.
- Q155: with no exit rule, suggest one once (*"You may want to consider defining an exit condition"*), never nag.
