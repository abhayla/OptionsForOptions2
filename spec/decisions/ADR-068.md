# ADR-068: First-screen rules the spec left open

## Why each part
- **Planned entry.** Why a user opens a draft: to see what happens if they enter now. A captured price gives exactly
  that and keeps REQ-033 AC-3 (scenarios never follow the current LTP). Following the live price would turn every
  expiry scenario into a live-LTP scenario; leaving entry empty would leave the payoff blank. The user reprices when
  they want "now" again.
- **Cadence.** Ticks arrive about once a second per contract (F-34); a 4-leg strategy would otherwise recompute and
  redraw up to four times a second for no visible gain.
- **UX level per request.** REQ-006 is not yet approved; ADR-004 already makes the level presentation only.
- **Leg picker.** REQ-067 AC-1 needs legs to be configured, and no other 4a item builds it.

## Alternatives not taken
- Entry follows LTP until saved (breaks REQ-033 AC-3 while drafting); entry typed by hand only (slow for a beginner).
- Push every tick (wasted work and redraws); REST polling only (REQ-048 AC-1 names the platform WebSocket).
