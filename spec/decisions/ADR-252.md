title: 'The "% of max loss" stop has ONE source: the playbook''s per-stage T-06 value at the strategy''s current stage'
decision: >-
  Orchestrator 2026-11-05 ~11:2x IST, decided under the owner's delegation ("For all the strategy related questions,
  you go with your recommendation"). The "% of max loss" stop line of every plan - saved before ADR-247 or after - is
  the playbook's trigger T-06 value for the strategy's current stage (weekly or monthly row), with the existing
  expiry-day tightening applied; the guard key stop_line_pct_of_max_loss is no longer a second source. The ADR-247
  iron condor version keeps T-06 at 50 / 50 / 40 % (early / middle / last stage): "50 % of max loss" in ADR-247 is the
  early and middle stage, the last stage is stricter, never looser. The same rule holds for the "% of margin" stop
  (T-16, off by default). Why: two sources disagreed - an admin tightening T-06 to 45 % saw no alert at a 47 % loss
  because new plans read a flat 50 % guard (test_system_playbook_versions core proof, 5 Nov) - and the plan words and
  the live alert must say the same number. Effect on ADR-250: saved and new plans now read their stop the same way, so
  no saved plan's last-stage line loosens; ADR-250 still keeps the 2x-credit stop off saved plans. Real case: strategy
  82 (Early stage) line 50 %, loss 50.04-51.19 % on 5 Nov morning. A default the user can change (ADR-245); decision
  support only (ADR-003).
  Addendum 2026-11-05 ~16:2x IST (same delegation; step 3 round 4 review): the plan sheet shows ONE stop number = the
  T-06 value of the strategy's own stage row (weekly or monthly) at its early stage. Saving the sheet changes T-06 only
  when the submitted stop differs from that shown value (a save that leaves the stop untouched rewrites nothing). An
  edit to V sets the early and middle stages to V and the last stage to min(V, its current value), so the last stage
  is never looser: 50 / 50 / 40 edited to 30 -> 30 / 30 / 30; edited to 60 -> 60 / 60 / 40. Switching a plan to a newer
  system playbook version is a new acceptance (accepted_at = the switch time).
