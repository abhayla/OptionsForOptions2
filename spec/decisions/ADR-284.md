id: ADR-284

title: 'The truncated-download guard judges a list by whether every stored expiry is still carried; a strike-grid change is accepted with counts'
decision: >-
  SPEC CHANGE of ADR-058 ("refuse the whole update, writing nothing, if more than 10% of an index's live contracts
  would disappear at once") and of ADR-059 ("a daily update is refused, writing nothing, if any one unexpired expiry of
  an index would lose more than half of its live contracts at once"). Decided under the owner's data-issues delegation
  (market-data expert role), GC-ICSAFE row c31, issue 680. (1) Per index, the daily update first asks one question:
  is every stored live group (expiry, option type or future) whose expiry is after the load date still carried by
  the new list? (2) Yes: the contracts that leave are a change of the strike grid, not a cut-off download. The update
  is accepted, the leavers are marked delisted as ADR-058 says, and the number that left is returned and logged.
  Neither the 10% count nor the half-of-one-expiry count refuses it. This includes contracts expiring on the load
  date itself: their leaving alone no longer refuses the list. (3) No, at least one stored group is wholly missing,
  or the new list has no row for the index: both counts of ADR-058 and ADR-059 run exactly as before, over every
  leaver. (4) A forced update is unchanged. (5) Only contracts the new list no longer CARRIES can be a strike-grid
  change. A contract that stops being live because its token now carries another contract (ADR-059) is always
  counted by both checks, whatever the groups look like: a list that reassigns many tokens is not a grid change. Why: measured on real data. On 2026-11-09 Zerodha narrowed NIFTY strike
  ranges; the list was complete and every later expiry was still carried, yet the guard refused it (2049 leavers),
  every day, until forced, and the builder showed no expiries. A cut-off file looks different: the real file is
  ordered by segment, then by expiry, then by strike, so a cut removes whole expiries.
