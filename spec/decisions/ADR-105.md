# ADR-105: Plan numbers in basket tags, stored first, one open plan

## Why
- The tag must let the return read-back find exactly this plan's orders. The domain version cannot do it: the real
  exit ran the active version v1 but had to be told apart from the entry, so its tag says V2.
- ADR-050 item 4(b) already requires the order intent to be stored before sending; ADR-054 applies it to the basket.
  A plan kept only in memory would be lost on a restart, and the next Execute could mint V1 again and adopt the
  morning's orders as its own.
- The design review found that, without one-open-plan, two exit presses produce two live exit baskets: the exit check
  compares against the held legs and does not see orders already in flight.

## Alternatives not taken
- The strategy store's save revision as the version: a save is not a plan, and an exit makes no save.
- A counter in memory, floored by Zerodha's book only: a basket built but not yet placed is invisible to the book, so
  two presses still mint the same number (review CRITICAL 1).
