# ADR-029: Security, compliance boundaries, audit and errors

## Rules
- Adapters for broker, market data, payment. Business rules server-side. Shared calculations central.
- Never: store broker credentials beyond the official token mechanism; expose vendor credentials to the browser;
  allow orders outside a strategy; bypass reconciliation blocks; let Advanced bypass safety checks.
- Compliance (T1 #26): applicable SEBI/exchange/broker-API rules must be validated before launch as a product
  requirement. Review list: personalised adjustment logic, advisory-like wording, notification content, data
  redistribution/licensing, exchange/vendor contracts, broker terms, the paid subscription, deletion retention (Q211).
- Audit: strategy changes, versions, rule evaluations, trigger values, approvals, order preparation/submission,
  broker responses, execution, reconciliation, external changes, entitlement changes, admin changes, security events,
  identity events (account created, email changed, Zerodha linked/session expired, trial started/expired,
  eligibility granted/revoked, referral reward, transfer, deletion, anti-abuse restriction).
- Error classes: input, strategy validation, market data, broker auth, broker eligibility, margin, order rejection,
  partial execution, reconciliation mismatch, notification, entitlement/access, internal.
