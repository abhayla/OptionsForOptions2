title: 'The ready-made Short Iron Condor places its strikes by a per-user preference (default: sold strikes at delta 0.20)'
decision: >-
  Owner 2026-11-06 ~14:2x IST (question tool, "This should be based on each user preference", then "Delta/SD/points;
  default delta 0.20"). Each user has a Preferences setting "Iron condor ready-made: place the sold strikes by" with
  one of three methods: (a) target delta (default 0.20: the listed OTM strike on each side whose |delta| is nearest
  the target), (b) standard deviations to expiry (default 1.0: spot +/- k x SD to expiry, nearest listed strike), (c)
  points from spot (default 100). The wing width is a separate setting in points (defaults NIFTY 200, SENSEX 500).
  The ready-made "Short Iron Condor" button builds from it; a user who never set it gets delta 0.20 and the default
  widths. Shift / Width / Hedge (REQ-078) still edit the result. When the delta method has no greeks (no live price),
  the button falls back to the points method and says so. Why: live test 2026-11-06: at NIFTY 24,693 the button sold
  24600 PE / 24800 CE with 100-point wings (range 24,519-24,881, ~half of one SD), close to an iron butterfly.
status: accepted

changes: 'Replaces the fixed placement rule in the ready-made iron condor template with a per-user preference.'
