# ADR-054: The order path is Kite's own order page

## Why this path
- NSE: "all orders received via API from clients / Algo Provider's platform shall be considered as Algo" (F-17); an
  algo provider's strategies must run on the broker's servers (F-18); a static IP maps to one client or one family
  (F-12, F-19). Sending many users' orders from our server fails all three.
- Zerodha: offsite execution sends users "to Kite's exchange approved order page where they place orders", "like a
  payment gateway", free, with a read-only basket and our tag per order (F-22).
- It also matches ADR-009 (the user executes) and ADR-002 (every order carries its strategy, via our tag).

## Paths not taken (and when they come back)
- (a) Exchange empanelment as an algo provider hosted on Zerodha's servers: ISO 27001, half-yearly VAPT, about 30
  working days, and unknown whether Zerodha hosts vendors (F-14, F-18). Back on the table if Zerodha says basket
  orders are algo orders.
- (c) The user types the orders into Kite by hand: always available as a fallback; loses the one-click plan.

## Open (owner action)
Zerodha's written answer: are offsite-basket orders placed by the user on Kite's page non-algo under NSE/INVG/69255?
How many orders may one basket hold, and how is a failed leg reported back?
