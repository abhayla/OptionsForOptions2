  Owner decided 25 Nov 2026 (about 22:35 IST) in the orchestrating cloud session; he first answered "2" (always ask
  before leaving) and then changed the answer to "1", which stands. The question corrected the premise of ADR-328 (2):
  the code shows that unsaved builder legs are lost when the user leaves the builder page, not when Option Chain
  "Add Selected" arrives.
  (1) Going from the builder to the Option Chain keeps the builder's unsaved legs. "Add Selected" then ADDS the ticked
  contracts to those legs; a ticked contract that clashes with a held leg asks the usual question (ADR-319 (1); the
  opposite-side case follows ADR-328 (1) for moves only, so a ticked opposite-side contract is a deliberate add and is
  not asked). This is the reading of ADR-007 Q34 ("all ticked contracts arrive in the Builder as legs") under which the
  builder's own legs are still there.
  (2) Leaving the builder for any other page while it holds unsaved legs asks first: "Leave the builder? The N unsaved
  legs will be lost." with two choices, "Stay" and "Leave". Stay keeps the page and the legs; Leave discards them.
  (3) ADR-328 (2) ("Replace the N legs?") stays for the case where the builder, already showing legs, receives a draft
  link that replaces them (a pasted or shared link, not the chain's Add Selected).
  Not chosen: ask before every exit, the chain included, with Add Selected starting from the ticked legs only; leave
  the silent loss as it is.

# ADR-329: unsaved builder legs are kept for the chain trip; leaving elsewhere asks first

Why: it decides what a trader keeps, and what he is asked before work is lost, so it is the owner's.
