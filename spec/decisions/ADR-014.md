# ADR-014: Market-data source: interim Zerodha live data, long-term licensed NSE+BSE provider

## Decision
- Interim V1 source: **Zerodha live market data**; visible *Connect Zerodha* guidance with step-by-step API/
  authorization setup (Q175, Q176). Historical deferred.
- Current Zerodha API/commercial terms must be verified before production (Q175, §39). Not a licence to ignore them.
- Long-term: licensed commercial provider, NSE + BSE, commercial SaaS redistribution rights, scalable WebSocket/API,
  historical rights (Q171, Q174, §71). Zerodha stays broker/account/execution authority.
- Evaluated so far: TrueData, Global Datafeeds (GFDL). TrueData said commercial NSE use may need an NSE
  certificate/document — **unverified; not encoded in product logic** (Q172).
- Selection checklist (Q173): raw data, historical, intraday resolution, Greeks/higher Greeks, chain fields,
  underlying/futures, depth, timestamps, contract master, expiry/contract events, API limits, WebSocket capacity,
  historical retention, redistribution rights, 5k/100k/500k economics, NSE coverage, BSE coverage.
- Never scrape NSE; never expose vendor credentials; never assume broker data can be redistributed (Q178).

## Direction changed across the handoffs (recorded, not hidden)
- 15 Sep §17: "centralized **licensed** market-data provider + Zerodha APIs for account/order/execution".
- Latest §5: "Do **not** rely on Zerodha as the sole public market-data source … confirm commercial licensing".
- Comprehensive Q175 / §39 (latest): interim V1 **uses** Zerodha live data, historical deferred.
The latest decision stands, but it reverses the earlier "not Zerodha as sole source" line, and that reversal is what
creates the conflict in Q204.

## Open
