  sells the 22,400 PE long (confirmed), each order tagged per ADR-105, with no further user click: all four legs are
  closed. If the 22,600 PE buy-back is rejected, the sequence stops, both longs stay open, and an alert is sent, with no
  retry. If the user''s Kite login has expired that morning, the stop cannot run and the screen says so from 06:00.'
- 'Exit sequence (REQ-100 AC-17): an automatic P&L exit (2) closes every leg in two phases. Phase 1 buys back each
  SHORT leg, one order at a time, each confirmed by Zerodha before the next is sent. Phase 2 starts only after every
  short is confirmed closed and sells each LONG (protective) leg, one at a time, each confirmed. A long is never sold
  while any short it protects is still open. A leg that is rejected, unknown or timed out halts the sequence where it
  stands, alerts the user, is never retried (ADR-017) and is reconciled (ADR-018): a halt in phase 1 leaves the

  premium paid. A strategy with only long legs is exited in phase 2 directly.'

# ADR-162: Automatic P&L stop-loss by the platform

Why: a beginner's real stop is usually a loss amount, not an index level, and the owner wants it to act without the
user present. Zerodha cannot hold a P&L condition, so the platform must send the exit; that makes it server-sent
trading, which carries the static-IP, algo-registration and server-uptime dependencies named above.
