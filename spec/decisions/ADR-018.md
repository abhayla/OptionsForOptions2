# ADR-018: Continuous reconciliation with Zerodha; broker state wins

## Decision
- Triggers (Q196): after execution · after reconnect · app start/resume · periodically for active strategies · on
  relevant broker/order events.
- Detects (§78): missing platform position, unexpected broker position, quantity/strike/side/expiry mismatch,
  external modification, partially executed strategy. Each mismatch records timestamp, broker state, platform state,
  difference, required next action.
- External Zerodha changes → detect, record, require reconciliation (Q197).
- Manual reconciliation: explicit and auditable (Q198).
- **Unresolved mismatch blocks new execution and adjustment execution** (Q199).
- Existing positions on connect (§50): fetch open positions, identify possible multi-leg structures; user can add to
  an existing strategy, create a new one, or leave standalone; once grouped, monitored as a strategy. The grouping
  algorithm must be explicit and auditable — its detail is open (§95).

## Open
Periodic reconciliation needs a valid Zerodha session; behaviour after daily session expiry is Q205.
