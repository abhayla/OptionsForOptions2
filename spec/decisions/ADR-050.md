# ADR-050: One instrument identity across brokers

## Evidence (measured 2026-10-02 from each broker's public instrument file)
- The same contract carries the same exchange contract number at Zerodha (`exchange_token`), Angel One (`token`),
  Upstox (`instrument_key` suffix and `exchange_token`), Dhan (`SEM_SMST_SECURITY_ID`) and Fyers (scrip code):
  NIFTY 06-Oct-2026 20050 CE = 40559 (NSE F&O); SENSEX 08-Oct-2026 75000 CE = 888931 (BSE F&O). 11,243 option
  contracts matched by (exchange, number) between the Zerodha and Angel One files.
- Zerodha's `instrument_token` is not shared (10383106 = 40559 x 256 + 2; inferred from two samples).
- Display symbols differ and some are not unique: Angel One `NIFTY06OCT2620050CE` (0 of 951 NIFTY symbols equal
  Zerodha's), Upstox "NIFTY 20050 CE 06 OCT 26", Dhan `NIFTY-Oct2026-20050-CE` (same symbol on 4 expiries). Angel One
  scales strike and tick by 100. Freeze limits differ per broker (3511 vs 3510). Some NIFTY expiries fall on Mondays,
  so expiry is read from the master, never computed from a weekday.
- The number is unique only within an exchange segment: always key on (segment, number).

## Decision
1. Identity: (exchange segment, exchange contract number), plus the descriptive cross-check (underlying, expiry, strike
   as exact decimal, CE/PE/FUT). Never key on a trading symbol.
2. Per-broker table: broker code (one vocabulary), broker token, broker symbol, broker segment code, master snapshot
   date; lot size, tick size and freeze limit with the date they were seen. A contract with no row for a broker cannot
   be traded at that broker (no symbol guessing).
3. The platform shows its own symbol format, built from the identity fields.
4. Order-path safeguards for the broker phase (P4): (a) our own tag on every order; on a timeout look the order up by
   tag, never resend (ADR-017 no automatic retry); (b) persist the order intent before sending; (c) consume Zerodha's
   websocket order updates and postbacks (checksum verified), with polling to recover gaps; (d) record orders placed
   outside the platform as external, never drop them; (e) rate limits per user key (10 orders per second, per minute
   and daily caps from Zerodha's current docs); (f) route an expired or replaced Zerodha session to re-login; (g) a kill
   switch per user and global; (h) Zerodha's API-order rules: non-zero market protection, at most 10 slices, at most 25
   modifications per order.
5. OpenAlgo (github.com/marketcalls/openalgo) per-broker layout - login, orders, data, response mapping, contract
   master, capability file - is a reference design only; no code is copied until its licence is checked. The
   algochanakya symbol converter, token manager and per-broker token table stay SKIP (keyed on a Zerodha symbol
   string; documented bugs).

## Alternatives not taken
- Keep Zerodha's instrument_token as the identity for V1 (cheaper today; a larger migration across orders, positions
  and ticks when a second broker comes).
- Copy algochanakya's canonical-symbol design (keyed on a broker string; weekly-format and expiry-day bugs).
