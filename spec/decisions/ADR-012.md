# ADR-012: Centralized, vendor-agnostic market-data architecture and shared computation

## Decision
- Pipeline (Q102): Vendor → Gateway → Normalization → Redis/fast cache → internal event stream → Option Chain /
  Strategy / Adjustment engines → WebSocket → Browser.
- Vendor-agnostic from day 1: one provider first; replaceable; multiple; fallback; more exchanges (Q103, §38).
- Normalized fields (Q104, §40): instrument id, underlying, exchange, segment, expiry, strike, CE/PE, LTP, bid, ask,
  volume, OI, OI change, IV, Greeks, timestamp, source metadata, data health.
- **Shared streams with internal fan-out; no per-user vendor subscription** (Q105, §84).
- Browser: no vendor connection, no credentials, no authoritative business rules, does not decide execution
  eligibility; it renders domain state (Q106, §85).
- Shared once: normalization, shared Greeks, underlying state, chain metrics, contract metadata, market-wide
  metrics. Per strategy: P&L, risk, rule evaluation, state, adjustment analysis, entitlement, alerts
  (Q107, Q108, Q170, §74).
- Scale target: ~5,000–6,000 users → 100,000+ → potentially 500,000 (Q109).

## Conflict
The shared-stream rule and the interim Zerodha data source (ADR-014) cannot both hold without Zerodha's
permission to share one account's data with many users: `spec/open-questions.md` Q204.
