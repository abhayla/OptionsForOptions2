title: 'Behaviours and numbers are settings, not code: admin default, user override, optional admin lock'
decision: >-
  Owner 2026-11-06 ~14:4x IST (question tool: "Yes: admin default, user can change" and "Yes, a lock per setting").
  (1) Every user-facing behaviour choice and every number in the iron condor / adjustment / alert / exit / money
  display flow is a setting in the one settings registry, never written into code: the admin sets the default for
  all users, each user may override it in Preferences, and a strategy's plan may override where the setting is
  per-strategy (the existing strategy -> user -> admin order). An owner decision about such a behaviour (e.g.
  ADR-255..263) becomes that setting's admin default. (2) Each setting has an admin "Users may change this" switch
  (default on); off, users see the admin value greyed with "Set by admin"; a number may also carry a user min / max.
  (3) Standing rule: every new feature adds its choices to the same registry the same way; older screens are moved
  when next touched. Not settings: correctness and safety rules (never an in-the-money delta pick, never a duplicate
  order, deleted strategies' alerts close) and page structure. Admin-only (not per user): server load and timing
  values (refresh intervals, request time limits).
