# ADR-043: Tech stack, and copying legacy code with provenance

## Decision
- **Q221 = A (owner, 2026-09-29).** Backend Python 3.12+ / FastAPI, PostgreSQL, Redis; frontend Vue 3 + Vite.
  Money uses Python `Decimal` end to end (ADR-008).
- **Why this stack.** It is the stack of `abhayla/algochanakya`, the only earlier project with a working Zerodha
  live-data pipeline and broker adapters worth adapting; the project's CI already runs Python 3.12. Spec basis for
  the question was none (the spec had no stack decision).
- **Copying legacy code (owner, 2026-09-29).** Allowed as COPY or ADAPT, per `spec/technical-design/legacy-reuse.md`.
  Conditions: (1) the copied file carries a header naming source repo, commit and path; (2) it is changed to meet every
  hard rule (strategy-linked orders, one engine, Decimal money, adapters, no automatic retry); (3) it gets this
  project's own tests — legacy tests do not count as proof (algochanakya's backend CI has never passed:
  0 successes in 200 runs, measured 2026-09-29).
- **Built new, not copied:** the calculation engine (every legacy P&L/payoff calculator uses floats and is duplicated)
  and order execution (legacy allows orders without a strategy and auto-executed adjustments).
