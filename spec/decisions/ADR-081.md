# ADR-081: Freeze limit - block at review, exchange file as the source

## Why
- A rejection that arrives after the user placed the other legs leaves a partial execution (a filled protective leg
  and a rejected short leg) the user must clean up.
- One order per leg keeps tag matching and partial-fill handling simple for V1's retail sizes.

## Alternatives not taken
- Split a large leg into slices: more partial states, and the basket's own size limit is unknown (ADR-054 open item).
- No check (Zerodha rejects): the partial-execution case above.
