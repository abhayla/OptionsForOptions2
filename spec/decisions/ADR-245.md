title: 'Every adjustment number and rule is a three-layer setting: admin default, user override, strategy override'
decision: >-
  Owner 2026-11-04 (question tool, "Yes, 3 layers for all"; and "always act as an expert option trader ... everything
  should be configurable ... what I answered is the default, which any user can change for himself"): every number
  and rule that shapes an adjustment - triggers and thresholds, stages, day-and-date rules, situations, approaches and
  their bases (ADR-243 roll basis), guards and limits, alert discipline (candle, cool-down, quiet time, daily cap,
  re-arm band), the carry-check gap, the S-02 and S-12 thresholds - is a setting with three layers: the admin's
  default (REQ-166 settings page), the user's own override (Preferences / his own playbook), and the strategy's plan
  override (REQ-161 plan sheet). The value in force is the strategy's, else the user's, else the admin default, and
  every flag, alert line and Compare cell names the value it used. An owner answer on an adjustment behaviour sets
  the DEFAULT, never a fixed rule.
  Exceptions: numbers that are not trading preferences stay admin-only (server timings such as poll and cache
  periods, worker refresh cadence, rate and connection limits, broker and exchange facts); each exception is named
  in the build's list with its reason.
  Why: users trade differently; the product is for option traders who set their own adjustment rules, and an
  adjustment must work the way that user's preferences are set.
status: accepted
