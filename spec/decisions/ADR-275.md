title: 'Paper and live are two modes of ONE code path: only the place a fill comes from differs'
decision: >-
  Owner 2026-11-08 ~16:2x IST, verbatim: "the fix or the code changes that we do should work for both Zerodha and
  live, and there should not be a separate code bases for both of them. It's just a way of testing same code but two
  different ways of testing. When market is open live, we can use Zerodha's live testing. Otherwise, if there are
  scenarios which can't be easily created in live, we can use paper trading for that and made up data for that."
  (1) A strategy's position, monitoring (triggers, stop lines, day rules, adjustment count), adjustment proposal,
  order basket and its sequence, partial-fill handling, expiry settlement, history and P&L are each ONE code path,
  used by paper and live strategies alike. (2) The only mode-specific step is where a fill comes from: the Zerodha
  adapter for a live strategy, a paper fill simulator for a paper strategy (ADR-029: the broker sits behind an
  adapter; paper is one more adapter). (3) Prices are a separate, independent choice: the live feed or made-up
  scenario data; either order mode runs on either price source. (4) A gap fixed for one mode is fixed for both; a new
  feature is built once and tested in whichever mode can produce the case (live market hours for Zerodha, paper on
  scenario data for cases the market will not produce on demand). (5) Unchanged: paper stays per strategy and
  labelled, a paper strategy never reaches the Zerodha order path (REQ-109), and the user presses to send every
  real order (ADR-003, ADR-016).
