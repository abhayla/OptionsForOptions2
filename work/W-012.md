# W-012: Strategy definition vs live state; activity history before execution, versions after

Separate definition and live-state objects; before first execution, changes are activity-history entries with restore; from first execution on, every meaningful change creates a new preserved version; a proposed version is separate from the active one and activates only after confirmation and successful execution/reconciliation; broker actual state wins over the intended version.

- **Core:** Editing a never-executed strategy creates history entries, not versions; after a (simulated) execution the same edit creates a proposed version that becomes active only on a reconciled execution result.
- **Proof:** tests/strategy/test_versions.py drives a golden Iron Condor through draft edits, a simulated execution result, a modification, and a partial broker result; asserts history vs versions, proposed vs active, and broker-actual quantities winning.
- **Spec basis:** REQ-038 and the decisions it cites; approved 2026-09-29 under ADR-045.
