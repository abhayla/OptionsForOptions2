# W-040: Brief quotes are checked against the spec before dispatch

Finding brief-rule-from-memory (11 occurrences on 2026-09-29): orchestrators wrote spec rules into briefs from memory and were wrong, and nothing compared the quote with the spec before dispatch. This item adds a stdlib-only checker that verifies each quoted citation verbatim (whitespace, straight/curly quotes normalised; `...`/`…` splits a quote into fragments that are each checked).

- **Core:** `python scripts/orchestrator/check_brief.py <brief-file>` exits non-zero and names the line when a brief attributes a quote to REQ-060 AC-2 that is not in spec/requirements/REQ-060.md's AC-2 text (e.g. "every run compares all non-exited strategies"), and exits 0 for a brief whose quotes all appear verbatim.
- **Proof:** run it on two real briefs: a bad one reconstructed from the W-037 brief (misquote) fails naming REQ-060 AC-2; a good one quoting REQ-058 AC-6 exactly passes.
- **Spec basis:** finding knowledge/findings/brief-rule-from-memory.json (its detection note: a check could "scan work items and briefs for rule sentences without a spec citation"); docs/process/builder-brief.md "Rules in your brief". No product requirement.
- **Scope note:** this is process tooling, not a product behaviour. No requirement is about brief checking (searched spec/requirements for "traceab" and "spec"; the hits concern product features), so REQ-067 (Delivery controls: built core-first and verified) is the honest closest link, and AC-1 is used only because it is the "prove on real input first" criterion. The checker cannot see paraphrases without quotes; UNCITED quotes are reported but only fail with `--strict`.
