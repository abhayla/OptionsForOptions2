# W-088: A real Zerodha login lands on the frontend page (#159)

- **RCA:** `kite_callback` and `_refused_redirect` redirected to a bare path. Kite calls back on the API's own host
  (`KITE_REDIRECT_URL`), the API serves no pages and the vite proxy forwards only `/api` and `/ws`, so the browser
  resolved the bare path against the API host and got a 404 (seen live 2026-10-08 and 2026-10-16).
- **Class:** every redirect the backend sends a browser to a frontend page: the callback's success plus all its
  refusals. Before: 13 of 13 resolved to the API host. After: 0.
- **Spec basis:** issue #159 (success shows the plain confirmation page, failure shows the catalogue message); REQ-015
  (Zerodha connection); REQ-065 AC-2 (a message states what happened truthfully); ADR-012 (the browser never holds
  vendor credentials: unchanged).
- **Fix:** new setting `FRONTEND_ORIGIN` (`broker_config.py`), validated at start-up (http/https, host, optional port,
  nothing else; one trailing `/` is dropped) and required with the broker routes. The response door
  (`errors._check_location`) accepts that one origin followed by a path from the existing allow-list, set once by
  `create_app`. The redirect code stays a member of the closed `REFUSAL_CODES`.
- **Unchanged:** the login route's `broker_login_busy` answers an error body by design.
- **Detection:** the class test resolves each Location as a browser does against the callback's host.
- **Not in this item:** changing the Kite developer-console redirect URL (not needed by this fix).
