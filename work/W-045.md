# W-045: Adjustment metric registry with a feasibility guard

A data registry holds the 30 reference-video values exactly as in the spec table, and refuses to register a calculator for any value whose feasibility is not `pass`. No calculators are built here (a later item); only the register/refuse mechanism, tested with a fake calculator.

- **Core:** A data registry holds the 30 reference-video values (id, name, source, frequency, calculation, feasibility) exactly as in spec/technical-design/adjustment-data-contract.md, and registering a calculator for a value whose feasibility is not "pass" (e.g. row 23, daily/1-hour candles, "fail for V1") is refused.
- **Proof:** tests/adjustment/test_registry.py loads all 30 rows and asserts each row's fields against the spec table (parsed from the spec file, not retyped), and that registering row 23 or row 20 raises; red first (module absent), green after.
- **Spec basis:** REQ-071 AC-1 and AC-2; spec/technical-design/adjustment-data-contract.md "Values in the owner's reference video" and "Owner readings of the unclear values (2026-09-29, Q246)" (rows 10, 26, 28 readings; rows 24-25 out of V1); REQ-047 AC-1 (no historical market data in V1).
