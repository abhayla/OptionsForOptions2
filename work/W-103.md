# W-103: audit events on both order routes

- **Spec basis:** REQ-063 AC-5 ("Audit and other stored payloads use a per-event-type field ALLOWLIST (each event type
  declares the fields it may carry; anything else is dropped before storage)"); REQ-073 AC-3 ("When the user returns
  from Kite, the platform reads the actual order states and positions from Zerodha and reconciles them"); W-017
  (`broker_response_recorded` = one Kite ORDER record, `execution_recorded` = one Kite TRADE record).
- **Requirements:** REQ-063 only. The brief listed REQ-063 and REQ-073, but `trace_check.py` refuses one work item
  delivering two requirements that share AC numbers (both have AC-1..AC-5). REQ-073 AC-3 (the return reads Zerodha
  back) is W-096's; this item's return-route events are REQ-063 AC-5 payloads, asserted in
  `tests_app/test_execution_return.py::test_core_real_order_return_entry_then_exit` and
  `tests_app/test_execute_route.py::test_core_real_order_entry_then_exit`.
- **Design:** `ofo_app/order_audit.py` is the one door both routes write through (database clock, at most once per
  correlation id: order = (order id, status, filled), trade = (order id, trade id)). Migration 0002 renders
  `allowlist_spec(through_revision=16)`; 0017 alone renders `order_prepared`, so its downgrade restores 0016's state.
