# W-036: Close Partial refusals return a result before any state change

Addresses #62. Found by the W-032 verifier (2026-09-29), outside REQ-056 AC-10.

- **Core:** close_partial_strategy with a freeze below one lot (or a held quantity not in whole lots) returns a
  "Nothing prepared: <reason>" result WITHOUT calling mark_closing, instead of raising after mark_closing.
- **Proof:** a test on the real catalogue fixture with a fake freeze below one lot: refusal result, strategy not
  marked closing, Complete/Retry not waiting for a newer read; red on origin/main, green after.
- **RCA:** close_partial_strategy calls mark_closing before the slicing validation, so a slicing refusal raises
  ValueError after the state change.
- **Class:** every refusal path in backend/ofo/execution/partial.py (close, complete, retry) that can raise or return
  after a state change (mark_closing, clear_closing).
- **Spec basis:** REQ-058 AC-6 "V1 never resubmits a failed order automatically; the failure is shown with its reason
  and the user chooses the next action (Q193)"; REQ-058 AC-2 (the four choices); issue #62.
