# W-025: Expected market range input: pick lists and validation

The range-input model behind the 'Not sure' flow: for a chosen expiry, two pick lists in 100-point steps (AC-5): the lower list from the current level downward, the upper list from the current level upward, each running to the furthest listed strike of that expiry in that direction (instrument catalogue) and capped by an Admin setting per index (defaults NIFTY 3,000, SENSEX 9,000 points); both values start at the current level and nothing is pre-filled (AC-3); the lower value can never exceed the current level nor the upper be below it (AC-6); the chosen range is carried as a labelled user input, never a prediction, into strategy and risk evaluation (AC-7). Pick-list values only: no typed numbers. Screen text (AC-2, AC-4) and the derivation of market characteristics (AC-1, AC-8) are left for the UI and discovery work (discovery waits on Q211).

- **Core:** For NIFTY at 23,237 with a real expiry from the catalogue, the lower list starts at the current level and steps down in 100 points to min(furthest listed strike, current - 3,000), the upper list mirrors it, and a lower value above the current level is refused.
- **Proof:** tests/range/test_pick_lists.py builds the lists from the merged instrument catalogue fixture (real Zerodha instrument rows) for NIFTY and SENSEX and asserts first/last values, step, cap and the refusals.
- **Spec basis:** REQ-026 and the decisions it cites; approved 2026-09-29 under ADR-045 (fourth set).
