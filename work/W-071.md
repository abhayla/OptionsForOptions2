# W-071: Save Draft and reopen in the Strategy Builder screen

- **Core / Proof:** see frontmatter.
- **Spec basis:** REQ-038 AC-5 ("A strategy's definition and its activity history are saved in the database when the
  user presses Save Draft, survive a restart, and load back exactly as saved; live prices are never saved inside the
  strategy. Each leg's planned entry price and its capture time are part of the definition and are saved with it
  (ADR-075)."); REQ-067 AC-1 (the first vertical slice includes Save Draft); ADR-068 item 1 (entries change only on
  reprice); ADR-075.
- **Found:** 2026-10-15 - the #208 builder found no frontend call to POST /strategies or GET /strategies/{id}; the 4a
  gate needs "the saved draft reloads unchanged" through the screen.
- **Card correction (2026-10-15, class 1):** the first builder found the API did NOT already cover the screen: POST
  /strategies takes each leg's internal `contract_id`, but no route the browser reads returns it (`ContractOut` has
  segment/token/expiry/strike/lot/symbol only), and a saved leg (`LegOut`) returns `contract_id` and symbol but not the
  segment and token the outcome API prices by. Decided by the orchestrator from ADR-057 ("A strategy leg, an order and
  an audit record link to the stored contract (its internal id), never to the raw token"): add `contract_id` to
  `ContractOut`, and `exchange_segment` + `exchange_token` to `LegOut` (both additive; save stays by internal id).
  Not chosen: saving by segment+token (moves the browser onto the raw token the ADR keeps out of the link).
- **Not in this item:** strategy versions/history UI, renaming, deleting drafts.
