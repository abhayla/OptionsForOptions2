# W-017: Per-event-type payload allowlist for stored audit/broker data (no stored credentials)

Each catalogued audit event type declares its payload fields; anything else is dropped before storage. Broker-response events keep only the listed Kite fields (order_id, instrument_token, exchange_token, status, quantities, prices, timestamps), never access_token, refresh_token, enctoken, public_token or api_key.

- **Core:** A real Kite login (session) response stored through the allowlist keeps no credential field, and a real Kite order response keeps instrument_token, exchange_token and order_id.
- **Proof:** Two REAL Kite responses captured from the owner's Kite Connect app (secrets replaced by placeholders AFTER capture, field names kept) as fixtures; the class-2 two-real-samples rule applies.
- **Spec basis:** REQ-063 AC-5; ADR-029 (never store broker credentials beyond the official token mechanism); independent review of W-015 round 2 (2026-09-29).
