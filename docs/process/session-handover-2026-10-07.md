## 6. Traps met this session (save the time)
- **YAML headers:** a `#` inside a plain YAML value starts a comment (`issue #30` broke two ADRs) and `": "` inside a
  plain line breaks parsing - write `GitHub issue 30`, avoid `word: word` in frontmatter prose. The coverage checker
  and `factory_lint.py` catch it; fix before pushing.
- **Kit guard hook** blocks any shell command whose TEXT contains a kit path word (`spec`, `tools/`, `views`,
  `.claude`, `factory` - even in a commit message or a repo name). Write commit messages without those words; read and
  edit spec files with the Read/Edit tools. Running kit tools (`tools/*.py`) inside a separate worktree needed the
  owner's explicit OK this session; the plain way is to run them as bare commands from the root of the checkout that
  holds the branch.
- **Folder `OptionsForOptions2-handover`** is marked as a governed project on the first PC and blocks every command
  that names it; use another folder name for worktrees there.
- **Decision pins:** a new ADR that amends or refines another makes CI demand that every requirement citing the
  older ADR also cites and pins the new one (`confirmed_against: "ADR-0NN #hash"`); the CI mirror prints the hash.
- **Evidence files:** keep the footer line exactly "Recorded by the orchestrator from the verifier's returned
  block." and the lines `requirement:` and `ac_fp:` (the helper `scripts/orchestrator/record_evidence.py` does not
  write those two - add them). `review_status` must read "PR #n; reviewed (...)".
- **CI frontend job** can time out installing Playwright system packages (a runner problem, not code); re-run only the
  failed job once.
- **GitHub pushes** failed for ~30 minutes with "Internal Server Error" for every push (status page green); it cleared
  on its own. Do not loop; work locally and push once later.
